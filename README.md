# ElectronicCalculator

Generated by `genfw` (framework: imgui).

## Settings

- `make` supports `linux`, `windows`, `avr`, `ch32` platforms. Change `PLATFORM` in
  `make/config.mk` or pass `PLATFORM=<platform>` on the command line.
- `make` supports `debug` and `release` modes. Change `MODE` in `make/config.mk` or
  pass `MODE=<mode>` on the command line.
- Allowed platforms/modes live in `make/config.mk` (`CONFIG_ALLOWED_PLATFORMS`,
  `CONFIG_ALLOWED_MODES`) - this is the single source of truth for both `make`
  and `genfw`.

## Make Commands

    make build       # build for PLATFORM/MODE
    make run          # build and run
    make watch        # hot recompilation
    make profile      # show last build's timing log
    make graph         # build/graph.png dependency graph
    make graph-html    # interactive build/graph.html
    make clean         # remove build artifacts

## Structure

```text
ElectronicCalculator
├── make/                  build system (config.mk, common.mk, rules.mk, lib.mk, <platform>.mk)
├── libraries/             each subfolder is an independent static library (its own Makefile -> lib<Name>.a)
├── src/
│   ├── core/
│   │   ├── main.cpp        the real entry point - compiled for every platform, plain C++ only
│   │   └── ...              framework glue (if any) also lives here - see below
│   ├── platform/<platform>/ ONLY exists per-platform when that platform's OS needs a different
│   │                         entry signature than plain main() (e.g. EntryPoint.cpp for WinMain).
│   │                         Such a file does nothing but forward into src/core/main.cpp - no other
│   │                         setup happens there. Most platforms won't have this file at all.
│   └── pch.hpp
└── tools/                 watch.py, dot_to_html.py
```

Every folder under `libraries/` with its own `Makefile` is built independently into
a static `lib<Name>.a` before the final link step - see `make/lib.mk`.

If a framework is generated (see `genfw`), its glue code also lives under `src/core/`
rather than being duplicated per platform, since it's ordinary portable C++ - only the
compiler/linker flags actually differ per platform, not the source.
